# Контракт сравнительных экспериментов этапа11

Ascon-AEAD128, AES-128-GCM, затем Kuznyechik-MGM; Magma-MGM только после приемлемого usage-budget и release gate из RUSSIAN_CRYPTO_INTEGRATION_DESIGN.md. Один hardware host/OS, pinned container images, CPU affinity/limits одинаковы, ARM отдельная серия. Для каждого provider: source revision, Python/C/Go/native backend, library/OpenSSL/compiler versions и optimization flags; незаполненное поле not_measured. Не сравнивать силу шифров по скорости.

Micro: 64/256/1024B и фактический canonical sensorJSON, одинаковый AAD из реальной telemetry. Warmup100, ≥1000 pairs/run, ≥3 (для убедительных CIs желательно≥10) независимых процессов, чередование порядка; новые ephemeral per-run keys, уникальные nonces, без превышения MGM budget. Magma короткие key-rotation batches: ключевой overhead отдельно, не обходить limit ради n=1000. Все implementations decrypt сверяет plaintext и отвергает tag mutation. Raw ns сохранять; mean/median/stddev/min/max, p95≥200,p99≥1000 условных measurements; повторяемость по независимым runs, не packet pseudo-replication. Доверительный интервал по run means, только при обоснованном количестве repeats/предположениях.

Pipeline: новые independent device identities/keys/SQLite, одинаковые3/10/25 cohorts, .5/1/2s interval, равные software resource constraints, TLS/HMAC/RBAC/CSRF неизменны. Static каждый profile отдельно; adaptive оба направления через adminHTTP. Не включать draft в live registry до KAT gate. Один cohort за раз; фиксировать фоновые micro/browser/fault нагрузки. Измерять scheduled→formed→publish→PUBACK и PG/Mongo отдельно по device/epoch/sequence; границы окна и unmatched записи явно отмечать.

Метрики: encryption локальный perf_counter, measured→received hostCLOCK_REALTIME, PGcommit not_measured без отдельного инструмента; Outboxcreated→finish включает relay+Mongo+PGfinish. ACK и effective timestamps отдельно; count transitions/unknown/retry/receipts, per-device fairness, resource Docker stats, DBconnections/backlog, bounded HTTP API и realbrowser. Нет интерполяции missing data; отсутствующую Mongo историю обозначать unavailable.

Reliability: поочерёдные Mongo/control/policy/PG/broker/device/receiver outages с сохранением исходных volumes; фиксировать before/during/after и backlogdrain. Никаких resetnonce/replay. Budget/stopconditions Stage10 сохранить либо ужесточить. Сравнение только при одинаковом workload; новые ошибки → остановить activation, сохранить evidence. Softwarex86 результаты не выдавать за физические RaspberryPi/энергопотребление/production capacity.

## Stage11: выполненная часть

Три software implementation сравниваются по [STAGE11_CRYPTO_BENCHMARK](STAGE11_CRYPTO_BENCHMARK.md): Python reference Ascon, native cryptography AES, Go Kuznyechik/MGM с one-shot IPC. Одинаковые payload/AAD, warmup, три независимых ключа/process runs; raw timings сохранены. Результаты не означают ранжирование криптостойкости или ARM performance. Magma не реализована и в результаты не включена.
