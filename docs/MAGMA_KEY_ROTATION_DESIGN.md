# Design only: short Magma ranges and rekey

No executable live profile. ICN candidate for a fresh independent per-device/profile/epoch key:8B big-endian encoding of strictly increasing per-key counter1..2^63−1 with MSB0. Global device sequence remains independent and may already be large. No truncation/modulo of the global sequence; actual invocation/block/verification budget is far smaller than nonce space.

A future versioned control/lease protocol must carry profile_id, explicit key_reference/epoch, independent short ICN range, invocation+block allowance, limits/version, request/boot ID and expiration. HMAC binds device/controller/direction/topic and every field. Old strict-schema v2 agents must reject v3 structures; no extra field slipped into old lease. New PREPARE/ACTIVATE requires provider/KAT/device readiness plus a provisioned key and budget. Telemetry wire migration must explicitly bind the new per-key counter; current deterministic coordinates cannot silently change meaning.

Atomic PG reservation under per-key row lock: debit full worst-case block/invocation allowance before grant commit, retain immutable reservation identity, no second debit on exact retry, no refund after crash or TTL expiry. Verification attempt allowance committed before tag verification. Unused/spent grants remain burned. Counter/ledger mismatch or authority rollback requires fail-closed reviewed recovery.

A new key must arrive via a separately designed authenticated confidential provisioning path, not plaintext MQTT commands or key bytes in SQL/Mongo/API. Controller needs evidence of key installation, epoch monotonicity, key separation and old-key retirement; transitions require actual target AEAD receipts. Missing SQLite/rollback cannot recreate counters under old keys. Until this lifecycle is implemented and independently tested, stop at exhaustion; no automatic reset or fallback. Across many epochs/keys aggregate bounds must be recalculated; rotation does not make aggregate risk disappear.

Current config also requires command_epoch == telemetry key_epoch. Frequent Magma rotation cannot silently increment one counter or reset the HMAC command ledger: future design needs an explicit independent telemetry-key generation binding, or a fully reviewed epoch reprovisioning protocol. Existing decoder's16B-tag assumptions and strict Mongo profile enum also need profile-specific compatibility tests before any future8B-tag profile. None is relaxed in Stage12.
