# Декларативные правила

Версия default-v1: configs/policy/default-v1.json. Только известные поля Rules;
никаких Python/SQL/скриптов/выражений. Целые параметры отвергают bool и числа вне
границ. Неизвестные поля отклоняются. Минимальный реальный профиль — только
ascon-aead128-v1; ослабляющая конфигурация не устанавливается.

| Параметр | Значение по умолчанию |
|---|---:|
| Окно replay evidence | 60 s |
| Максимальный возраст / допустимое будущее | 120 / 5 s |
| Подтверждения WATCH / ALERT | 2 / 3 |
| Cooldown | 30 s |
| Непрерывное восстановление / число наблюдений | 300 s / 6 |
| Свежесть телеметрии / ML | 60 / 120 s |
| Интервал решений | 1 s |

Повышение: повторные аутентифицированные replay, а не средний ML score.
Подтверждённая critical security_violation обходит cooldown/rate limit.
Физические правила дают WATCH; ML anomaly может дать рекомендованный WATCH,
но не подтверждённую атаку или реальное управление. adaptive_research влияет на
модельный observed risk только в SIMULATION.

Восстановление: минимум заданное число accepted, непрерывная история не короче
recovery_seconds, свежий ML результат со статусом ok, без новых аномалий.
Разрыв телеметрии больше freshness сбрасывает стабильный период. ML availability
не делает модель доверенной; её anomaly прерывает восстановление, отсутствие
результата не становится нормой. Initial NORMAL также требует свежего scored ML
и минимум двух подтверждённых измерений. Без ML риск остаётся UNKNOWN.

Переходы вниз и в UNKNOWN учитывают cooldown; guard не ослабляется при UNKNOWN.
min_decision_seconds ограничивает частоту audit decisions, а подтверждения
сохраняются и для rate_limited сигналов. Поток частых событий не сдвигает таймер
бесконечно. Управляющее намерение возможно лишь при новом переходе и изменившейся
рекомендации, без повторов того же requested profile; оно никогда не отправляется.

Поздний occurred_at меньше последнего учтённого времени получает late; слишком
старый — stale; слишком будущий — future. Они остаются в аудите, но не меняют
риск задним числом. Неизвестные версии/semantics дают диагностическое отклонение.

POST /api/policy/versions: admin + CSRF, поля version/rules/activate. Версию нельзя
перезаписать другим config. Активация записывает actor/action/time в аудит.
