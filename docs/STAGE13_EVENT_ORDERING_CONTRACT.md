# Stage13 event ordering contract

No timestamp/UUID high-water cursor. Durable pending identity exists independently of the active policy version, in the same PostgreSQL transaction as the source insert/status change. Late commit, including occurred_at T+5 after T+10 was processed, cannot become invisible. It is consumed and receives the existing FSM late/stale diagnosis, rather than retroactive state rewriting.

One global policy transaction lock serializes bounded batches and install/activation. Multiple accidental worker processes are serialized, not an advertised parallel speedup. No SKIP LOCKED can skip E1 and process E2 concurrently. Within each source kind, ordering is (occurred_at,id) for security, (available_at,id,status identity) for ML, with bounded alternating source fairness. A batch captures a bounded snapshot; events committed afterward are discovered next batch, even if their timestamps are older. This is not event-time omniscience.

Global discovery identity is not a global processing checkpoint. Completion is the existing unique policy_signals(event_id,version), with state/decision/transition/intent and dequeue in one transaction. Activation enqueues all retained unconsumed source identities for that version. No source trigger reads or locks the active policy version: concurrent capture cannot miss activation or wait on the policy transaction lock.

Synthetic ML-unavailable/telemetry-stale evaluation runs at most once per periodic maintenance transaction (runtime cadence5s), only for a device with no committed real pending items visible in that snapshot. An unrelated device backlog does not disable stale detection for silent devices. It retains the previous deterministic expiry identity, bounded scan and guard semantics. A subsequent older committed event remains audited as late under the same existing FSM rules. A zero queue is not healthy evidence.

ML status updates are mutable in the original source table. The durable pending entry snapshots each distinct non-processing (event_id,status), preserving the original adapter identity and explicit provenance. Two status changes committed before polling remain diagnosable instead of silently overwriting an unread status; this is an explicit discovery improvement. No trust or score meaning is upgraded. Exact duplicate status identities remain per-version idempotent.

The next source preference is stored in the singleton policy_schedule row, advanced with dequeue/markers in the same transaction. An odd-length time-bounded batch or restart does not reset the alternation. This is not parallel claim scheduling; all worker/activation/prune transactions use the same transaction advisory lock.
