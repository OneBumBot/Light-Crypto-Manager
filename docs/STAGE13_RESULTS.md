# Этап 13 — Policy throughput, ordering и reliability

Baseline: `feature/crypto-comparative-research`, `649a80ff7f7d66f72f5f483b384754ae594f221e`; новая ветка `feature/policy-engine-throughput-hardening`. Main не изменяется; push/merge/rebase не выполнялись. Финальный commit определяется `git rev-parse HEAD`; исходные/runtime hashes каждого опыта сохранены независимо от финального коммита документации.

Исходная полная регрессия **882 passed,0 skipped /41.80s /exit0**; после изменений **922 passed,0 skipped /52.09s /exit0**, настоящие PG/Mongo. Исходные алгоритмы и KAT/telemetry/poison/replay/nonce/TLS/HMAC/control/Outbox/RBAC/CSRF/Socket.IO/ML/Ground Truth tests сохранены. [Лог](reports/stage13/full-regression-final.txt). Количество тестов не является доказательством качества IDS.

Добавлена additive migration0011_policy_throughput после0010_mgm_key_usage. Source transaction атомарно формирует indexed pending snapshot. Timestamp/global high-water cursor отсутствует: поздний committed event обнаруживается независимо от occurred_at. Bounded batch использует существующий lock activation/retention, текущую версию и transaction-local Rules; source completion, FSM/state/decision/transition/proposal/dequeue/fairness коммитятся вместе. Повторная попытка защищена существующим unique(event_id,version), не повторяет decision/intent. Новые multi-worker попытки сериализованы; horizontal sharding не заявляется.

Подтверждены несколько разных затрат: unconditional sleep, full-history anti-join, per-event commits и повторный Rules lookup. Повышение batch_size само по себе не решает их. Matched synthetic ablation: median24.22→433.00 events/s при идентичном FSM результате; не использовать этот показатель как MQTT capacity. Live25-device baseline обрабатывает около25 events/s из50, optimized соответствует поступлению. Live50 измерено≈99.9 observations/s, pending2 на снимке и0 после drain. [Все измеренные runs/ограничения](STAGE13_PERFORMANCE_RESULTS.md), [SQL](STAGE13_SQL_OPTIMIZATION.md).

Pure engine/rules не изменены.13 golden traces сравнивают state/risk/guard/diagnostics/transitions/recovery/recommendation/applied/effective и полный порядок process calls при фиксированном времени; исходная реализация frozen отдельно.24/24 поведенческих мутаций обнаружены после устранения двух реальных пробелов покрытия. Обнаружен и исправлен внутренний ML ValueError consumption bug. [FSM](STAGE13_FSM_EQUIVALENCE_TESTS.md), [reliability](STAGE13_RELIABILITY_RESULTS.md), [матрица](STAGE13_E2E_TEST_MATRIX.md).

Доступность worker и свежесть источников разделены в `/policy`, `/api/policy`, `/api/policy/metrics` и monitoring. Очередь/возраст источника/heartbeat/capacity/overflow — отдельные поля. Рекомендация с устаревшей authenticated telemetry помечается stale даже при недавнем ML/state update. При ошибке API/PG браузер удаляет старое содержимое. Используется textContent, bounded same-origin/no-store requests; новых control actions нет.

Новая версия заново обнаруживает retained source identities без marker этой версии. История не переписывается; old guards/cooldown semantics сохранены. Source insert не берёт activation lock, поэтому гонка commit/activation не теряет источник. Synthetic stale не обгоняет pending real source своего устройства, но чужой backlog не скрывает stale silent device. ML/security alternation durable; ML всегда research/untrusted, отсутствие ML не NORMAL.

**Безопасность:** Policy DRY_RUN; настоящие crypto commands только manual admin+CSRF через прежний durable Control Worker. Ascon/AES/Kuz crypto/math/keys/nonces/wire format не менялись. Единственное Kuz release дополнение — явный Stage13 test namespace при прежних gates, lab-only сохраняется. Magma отсутствует в live control. Старые volumes/ключи/научные артефакты не используются и не удаляются.

Остаточные ограничения: один serialized worker authority, capacity/retention100000, activation seed/replay cost, bounded input/statement timings, software host only; нет HA/ARM/trusted IDS/production Kuz claim. Между old/new worker бинарниками нет безопасного mixed rollout: остановить old, upgrade, стартовать new. Для последующего RF/IF исследования инфраструктурная обработка улучшена; доказательства label/source/dataset качества и отдельное разрешение на обучение всё ещё необходимы. Автоматического control доверия это не даёт.

Команды воспроизведения и stop/resume: [design/runbook](STAGE13_POLICY_THROUGHPUT_DESIGN.md). Raw machine artifacts, exit codes и графики находятся в [reports/stage13](reports/stage13/). Незавершённые/перекрывшиеся при восстановлении короткие измерения явно исключаются; отсутствие отчёта никогда не трактуется как успешная проверка.
