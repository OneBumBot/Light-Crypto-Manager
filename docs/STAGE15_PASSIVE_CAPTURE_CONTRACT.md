# Passive capture contract v1

Capture point is lab-devices eth0: same veth Ethernet publisher namespace as Stage14, broker TCP8883 only, both directions, tcpdump-p (no promiscuous mode), NET_RAW only. IPv4/TCP/Ethernet classic PCAP, actual captured frame length; raw16bit window,9bit NS+flags. No VLAN/IPv6/fragment reassembly/offload portability claim. TLS opaque; packet bytes saved only in private bounded PCAP, journal has five headers/digest/context, no payload/credentials. Snaplen262144 (-s0), included/original length equality required; max65535 supported frame. Offload settings not changed or inferred as universally safe; parity validates actual observed frames in this environment. Libpcap kernel CLOCK_REALTIME timestamps, micro/nanosecond PCAP units decoded. No cross-host time accuracy claim.

Global PCAP header and per-record lengths validated incrementally; malformed/truncated stream fails closed. Reader has512bounded pendingframes, SQLite512pending events/50000total,1024LRUflows/60s expiry, max20000packets/60s capture,32MiB PCAP, free disk floors. Detector/model container512MiB/1CPU, capture128MiB/0.5CPU, bounded logs/pids. No indefinitely running capture. Raw source/resource truncation never reported as complete. Clean early signal creates incomplete capture, SIGKILL leaves missing final stats and stale heartbeat, not a fabricated drop0. Kernel drop count not measured until tcpdump exits; reader/application loss counters separate. TCP sequence gaps observable but do not prove detection of every missing ACK-only packet.

Packet identity: unique capture UUID+record ordinal, raw frame SHA andcapture timestamp. Bidirectional key is unordered endpoint pair; direction metadata separate. First initial SYN defines complete generation anddelta0. Missing SYN/midstream/expiry creates insufficient context. Changed SYN ISN or SYN after FIN/RST creates new generation; retransmitted SYN with same ISN in open flow remains same generation. Subsequent timestamps use preceding observed packet both directions. Negative delta never clamped; flow invalid until new generation. TCP sequence continuity tracks sender separately, retransmission preserved,forward gap invalidates context. Sequence32wrap is transport arithmetic, unrelated to AEAD counters.

A capture-wide queue/drop gap makes later results invalid/provisional. No confident normal verdict. New run/generation/context evidence needed; raw historical scores remain audit records, current UI clears on incomplete/stale/unavailable source. All online results provisional until final kernel stats. Observer restart creates fresh capture UUID; same tuple cannot inherit another run's state. SQLite is research-only, not a nonce authority.
